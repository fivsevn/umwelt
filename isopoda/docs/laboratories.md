# 阿西莫夫姐妹实验室维护契约

[返回文档导航](README.md)

形态实验室与环境实验室都是公开的作品页面，也是作者的资料与布置工具。沿用阿西莫夫的名字和像素世界叙事；专业资料与编辑工具集中在实验室，不因资料扩充而自动搬入游戏界面。两者应随游戏内容一起维护，不能在游戏扩充后长期停留在旧目录。

## 同步责任

| 扩展内容 | 形态实验室 | 环境实验室 |
| --- | --- | --- |
| 新鼠妇或其他等足类 | 共享物种目录、名称、形态、来源与不确定性、阶段/动作展示 | 共享目录中的比例参考、环境资格、当前环境尺度 |
| 新环境或布景 | 涉及物种的生态/来源资料 | 环境预设、素材分类、共享布局与绘制、导入导出、点选拖动 |
| 新动作或成长阶段 | 姿势/阶段控制与形态展示 | 比例参照及受影响的表现；保持布置工具的边界 |
| 新语言或叙事 | 标签、资料、互链的覆盖范围 | 标签、状态与帮助说明的覆盖范围；明确哪些专业用语保留 |

新增资料需要可核查来源，不能把视觉代理或游戏参数当作生物学事实。延续 [物种契约](species-data-contract.md) 和 [形态边界](morphology-renderer.md)。

## 入口与数据

- 形态实验室：`/isopoda/morphology/`，入口模块 `../morphology/app.mjs`。
- 环境实验室：规范文件 `/isopoda/habitat.html`；线上 `/isopoda/habitat` 也可访问。编辑模块 `../habitat-lab.mjs`，布局编解码 `../scene-codec.mjs`。
- 两页从 `../species-registry.mjs` 读取标本。环境实验室展示完整目录（参考种明确标注），预设的默认参照从相应环境的可玩种中选择；导入时保留作者指定的参考标本。
- 环境配置来自 `../habitats.mjs`，已采用布局来自 `../scenery/authored-layouts.mjs`，游戏与实验室使用共享的形态像素和游戏比例投影。
- 素材库及预设按钮仍有显式入口，新增环境不能只写一份布局。需同步素材定义、分类适用环境、背景映射、按钮、运行配置及测试。参见 [环境扩展指南](environments.md)。

## 编辑与发布边界

环境实验室的改动只在当前页面内生效，不直接写游戏存档或仓库。刷新、离开、切换预设或 RESET 会丢弃未导出的编辑；作者应先导出 JSON 或分享代码。导入需同步预设/素材库，并在解析或绘制失败时保留原布局。

将导出布局用于游戏仍是独立的开发变更：核对稳定对象身份、位置、角度、镜像、层级、素材参数、存档与交互，再更新共享布局并验证。不要把参考标本的示意位置当成游戏群体配置。

每轮扩展必须在提案中明确两个实验室的影响：需要同步的内容、验证结果，或不受影响的原因。运行统一检查，以及 [两页浏览器回归](../../tests/README.md)，核对互链、窄屏、资料目录和环境编辑。实验室内部科学资料的增长不应破坏游戏的沉浸表达。

## 参考资料归属（全游戏统一原则）

游戏 `credits*.md` 只列数据库、出版社、期刊或机构主页，以及两个实验室的入口。不可在任何位置另增某篇论文、物种详情页、环境科学说明或具体功能的参考文献段落；新增来源平台时同步四种语言的主页列表。

具体资料按其支持的内容一一对应：

- 物种的分类、体型、分布、生态和行为 → 形态实验室该物种的 **当前标本参考**。将文章写入共享来源注册表，并加入该物种的 evidence IDs；不可只添加在一个不关联物种的全局列表里。
- 环境的地貌、水文、物质迁移、测量尺度和场景依据 → 环境实验室该环境的 **当前环境参考**。在 `data/habitats/references.mjs` 记录 source ID、支持的内容与适用范围，由 `habitat-references.mjs` 随预设切换显示。
- 同一资料同时支持物种与环境时，共用来源记录，在两处分别解释其支持的内容；不要复制来源，也不要搬回游戏 Credits。

两个实验室承担全部详细背景资料。游戏里的阿西莫夫笔记和剧情基于这些证据做叙事表达，不复述论文摘要。虚构路线、数值和时间尺度的说明留在对应实验室。

维护检查必须扫描 Credits 全文，防止在“主要资料来源”以外追加论文段落；同时核对物种/环境 source ID 能解析到具体来源，切换目标后没有串用其他目标的参考。
