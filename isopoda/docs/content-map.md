# ISOPODA content map

This document is the development entry point for authored content. It separates active game content from legacy or reference material so new work lands in the correct module without changing the current public UI.

## Terrestrial seven-day run

### Active

- `content.mjs`
  - `EVENING` — night observation text.
  - `AMBIENT` — state-dependent ambient observations. This is active runtime content.
  - `CARE` — morning care choices and feedback.
  - `MINI_TYPES` — midday interaction type rotation.
  - `ENDINGS` — terrestrial ending copy and stable ending IDs.
- `encounters.mjs` — authored encounter choreography, titles and visible observation lines.
- `engine.mjs` — scene assembly and some midday authored copy. Prefer moving new large content pools into data/content modules instead of expanding the engine with prose.

### Legacy / do not extend

- The unused `content.mjs:MORNING` export was removed after checking runtime, save migrations and tests for consumers. Its original text remains in Git history (pre-cleanup main `08a3613`). Do not recreate it.

## Ordinary aquatic three-day runs

- `aquatic-story.mjs` — routing, stable text keys, endings and state-to-story selection.
- `data/habitats/stories.mjs` — the nine base turns for freshwater, intertidal and shallow-marine habitats.
- `data/habitats/story-alternates.mjs` — conditional alternate turns selected from environment state.
- `habitats.mjs` — habitat configuration, eligible species, duration, metrics and stable habitat IDs.

When expanding aquatic content, add authored rows to the habitat data modules and keep `aquatic-story.mjs` focused on routing. New habitat definitions must also satisfy `tools/validate-habitats.mjs`.

## Abyssal single observation

- `habitats.mjs`: `days:1`, `turns:15`, `dialogue:true`, `cohortSize:1`, eligible species `giganteus`.
- `data/habitats/abyssal-dialogue.mjs`: 15 ordered dialogue nodes with stable node/option IDs, localized prompts/responses, ending fragments and ending data.
- `aquatic-story.mjs`: dialogue routing, option presentation order and trace-based ending assembly. No ordinary three-day timing; do not derive its length from `days * 3`.

## Species and specimen content

- `species-registry.mjs` is the shared enriched runtime boundary.
- `data/species/manifest.mjs` owns specimen batch append order.
- `data/sources/manifest.mjs` owns evidence/source batch append order.
- `species.mjs` contains the original terrestrial table.
- `data/species/batch-*.mjs` contains accepted-species expansion batches.
- `data/species/hobby-lines.mjs` contains captive/trade lineages.
- `data/species/aquatic.mjs` contains playable aquatic taxa.
- `data/species/marine-reference.mjs` contains reference-only marine material.
- `locales/annotations.mjs` contains localized specimen annotations.
- `data/wiki/` and `data/sources/` contain provenance/reference support.

Stable species IDs are save/archive keys. Do not rename them as a copy-edit.

## Localization flow

- UI copy: `locales/ui.mjs`.
- Legacy terrestrial authored copy translations: `locales/game.mjs`.
- Specimen annotations: `locales/annotations.mjs`.
- Fictional isopod language: generated by `locales/isopod.mjs`.
- Credits: `credits*.md`.

Visible active terrestrial source strings must be represented in the locale table. The i18n checker treats `AMBIENT` as active. New content follows `narrative-contract.md`; existing Chinese-string mappings and aquatic/abyssal triples remain compatibility paths.

## Safe expansion checklist

1. Choose the correct content module before writing prose.
2. Preserve existing IDs and storage keys.
3. Register new specimen/source batches through the manifests without reordering existing groups.
4. Add EN/JA coverage in the same change where required.
5. Add or update tests when a new condition, habitat, ending branch or species eligibility rule is introduced.
6. Run `node isopoda/tools/check-all.mjs` plus the relevant browser regression harnesses.
