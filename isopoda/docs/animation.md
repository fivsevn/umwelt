# 动画与动作扩展指南

[返回文档导航](README.md) · [形态渲染边界](morphology-renderer.md)

动作不是只增加一个姿势名称。需要同时确认触发、持续、退出、绘制和交互覆盖关系。以下记录当前接入位置，未启用任何新动作。

## 动作链路

| 层 | 当前入口（相对 `isopoda/`） | 职责 |
| --- | --- | --- |
| 行为与阶段 | `behaviors-speed.mjs`、`encounters.mjs` | 个体推进、场景角色、动作与姿势选择 |
| 指针交互 | `interaction.mjs` | 触碰、拾取、防御和恢复；支持能力决定蜷缩或其他防御 |
| 运动档案 | `locomotion.mjs`、`data/locomotion/` | 速度、步频等模拟系数及独立研究依据 |
| 解剖像素与姿势 | `sprites.mjs` | `POSTURES`、`pixelAnatomy`、`setIsopodState`、蜕皮区域 |
| 游戏合成 | `habitat.mjs` | 动画相位、像素缓存、朝向、遮挡与画布输出 |
| 水生行为与反应提示 | `scenery/aquatic.mjs`、`reactions.mjs` | 水生推进与独立的反应表现 |

游戏画布和 DOM 标本视图使用不同缓存路径。两条路径都需核对，不能只在形态实验室看到动作就认定游戏已接入。

## 下一轮实施清单

1. 说明动作的触发和退出条件、允许物种/成长阶段/环境、与拾取、防御、蜕皮和其他行为的优先级。
2. 确定动作是否影响游戏状态或仅表现。需要保存的新身份/状态按 [存档兼容](save-compat.md) 处理；渲染层不反向修改剧情。
3. 检查姿势白名单、行为分支及像素生成是否一致。当前相位按四帧处理，两个渲染路径的缓存键均包含姿势/蜕皮/相位/移动状态；增加帧数或输入参数必须审计全部消费者与缓存键，不能只增加图形分支。
4. 保留物种能力限制、像素网格、朝向与遮挡规则；动画调参写在 simulation，不能伪装成生物测量。依据见 [运动研究说明](../data/locomotion/README.md)。
5. 检查固定种子下的输出、动作结束后的恢复及交互抢占；覆盖不同体型、阶段、陆水环境和速度切换。运行 [验证矩阵](expansion-guide.md#验证选择) 中的相关测试及两个实验室/主游戏浏览器检查。

如果动作增加可见描述、提示或新结局条件，还要同步走 [叙事](narrative-contract.md) 与 [语言](languages.md) 路径。
