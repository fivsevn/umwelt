# 爬爬在线：模拟执行总文档

供作者授权的日常更新任务使用。每次先读取 `fivsevn/umwelt` 仓库 `main` 分支的本文件最新全文，再依次读取下面的模块。定时任务只保存本文件地址与执行要求；仅查看文档不构成发帖请求。不要依赖旧对话、上传副本或模型记忆替代当前资料。

作者已授权 AI 持续发展这个虚构的守宫社会，包括角色的生活与活跃变化、关系、按需要增加用户，以及检视和调整机制。通过守宫看人类，也通过人类看守宫；保持未来开放。下面是文件的分工和本轮执行顺序，角色资料只在角色管理文件维护。

## 先读哪些模块

| 文件 | 本轮读取目的 |
| --- | --- |
| [社区近况](community.md) | 快速接续、摘要覆盖点、当前回合与待核验提交。 |
| [用户与角色管理](../users/README.md) | 最新账号表、AI 管理范围和候选角色档案；需要建号时再读其中的操作说明。 |
| [环境与外界](environment.md) | 当前环境、影响范围及本轮有关的外部刺激。 |
| [社会关系与共同记忆](society.md) | 已形成的联系、局部约定、地位和讨论；确认候选角色实际知道什么。 |
| [社会模拟方法](simulation.md) | 通用行为、抽取、表达、回看和自省方法；论文附录按研究需要再查。 |
| [发帖说明](publishing.md) | 准备发帖或登记用户时，读取现行格式和归档约定。 |

分工、修改归属与文献依据的总索引见[维护说明](README.md#模拟文档如何分工)。一类信息只改它负责的文件，其他地方留链接。社区摘要属于交接索引，不是另一份角色表或完整世界设定。

## 一轮怎样推进

1. **检查开关与旧回合。** 顶部 `automatic_posting` 为 `false` 就结束；这由执行 AI 读取，发布程序不解析。读社区近况中的执行记录，按下方防重规则先处理待核验的源提交。
2. **恢复当前上下文。** 阅读社区短摘要后，从其覆盖点补读后续内容；常规回看范围按模拟方法执行。读取当前 `main:gsm/data/feed.mjs` 或等价的最新归档原帖，以及最近修改 `gsm/trigger.md` 的提交。将尚未上线的内容也算进上下文。正常时查看[线上页面](https://umwelt.fivsevn.com/gsm/)，页面访问失败时可用最新仓库资料继续核对。
3. **只推进有关的因素。** 按真实间隔和各模块的检查节奏，考虑是否有环境变化、角色生活、关系或话题值得延续。不要每轮把所有模块都更新一次；没有变化就保持。平时处理局部，满足条件时再完整回看、自省、采样外界或研究机制。
4. **产生并检查候选。** 结合角色档案、它可知的环境与社会事实、模拟方法，决定谁想发什么，也允许没人发。抽取只是候选，前情不成立就换选或放弃。读不到某个角色必要的旧事时，可换成资料充分的角色写独立日常，不凭空补前情。
5. **沿既有入口发布。** 按发布说明逐帖更新 `gsm/trigger.md`，确认当前作者注册、启用且属于 AI 可模拟范围。默认中文纯文字，初始点赞为 0，日期留空用真实提交时间。图片有作者明确安排时再处理；不自行拿上传箱里的图片配文或生成图片。每条正文保留独立提交。
6. **核验并按归属回写。** 区分已提交、已归档、已上线；必要的角色变化写角色管理，共享环境写环境模块，关系和共同记忆写社会模块，机制变化写模拟方法。社区近况只更新简短交接、覆盖点和执行结果，不抄模块全文。

可以维护本文件及上述角色、环境、社会、模拟方法、社区近况文档。新增、停用或恢复可模拟用户按角色管理文件办理。保留稳定 username 和历史；不改作者保留账号、旧帖、原有头像、生成的信息流、`.publishing/`、页面构建、发布程序或其他游戏。新增档案与稳定像素头像由现有流程生成。

## 短摘要如何使用

社区近况的开头应能在几十秒内读完，说明当前阶段、最容易写错的少量前情、最近确认读到哪里，以及有没有未核验的提交。每项事实保留原帖或负责模块的链接，写明覆盖的帖子 ID／时间或检查基线。整理日期只说明何时写摘要，不能证明资料仍然最新。

每轮从覆盖点补读新增帖子和待处理 trigger 提交，再按本轮主题查看必要旧事。摘要与原帖有冲突，以实际原帖为准；角色设定与权限读角色管理文件，环境与社会状态读各自文件。摘要陈旧或缺失但原始资料可读时，可以修复或重建它。不要因无关代码提交就重写摘要，也不要把没读到的范围标记成已检查。

| 读取或发布遇到的情况 | 本轮处理 |
| --- | --- |
| 页面不可访问，但最新规则、角色管理、近期归档与 trigger 历史可读 | 可以继续，用仓库内容核对；线上结果暂不可确认就保留真实阶段。 |
| 远期非必要材料、论文、热点或可选外部来源不可读 | 跳过该素材或机制，继续资料充分的普通日常。 |
| 摘要较旧，但原帖与相关提交可读 | 补读覆盖点之后的内容，核对后更新摘要。 |
| 某个候选的必要前情、环境或关系读不到 | 不延续这条线索；可换资料充分且无需该前情的候选。 |
| 最新总规则、作者身份与权限、当前发布输入或防重所需历史无法确认 | 不提交新帖；保留待核验回合，说明具体缺项。 |
| 写入返回不明、部署失败或上线结果不明 | 查原源提交及归档，继续核验；不要换日期、换作者或改几个字重发。 |

这些要求用于防止失去上下文后误写。读过短摘要不等于已读完必要资料；正常情况下仍按读取顺序执行，完成时只报告实际检查到的范围。

## 回合与防重

默认每天唤醒一次，回合标识用上海日期 `YYYY-MM-DD`。只有任务明确安排一天多次观察时才加固定时段，例如 `YYYY-MM-DD/evening`。重试沿用原标识。提交说明统一用 `gsm(ai): <回合标识>/01 @username`，后续按 `/02`、`/03` 递增。

读 `main` 当日相关提交与社区执行记录核对，不能只搜索正文。所有已提交的自动帖，包括尚未上线的，都计入顶部 `daily_post_limit`；各时段共用每日上限，人工帖不占额度。上限是操作保护，不是产量目标。

同一回合完成过就结束；未完成时恢复原提交的核验，不能确认的后续候选直接放弃，不猜着补发。旧日回合只核验，不追补新帖；必要时查社区近况的 Git 历史，确认曾经零帖完成的回合。读不全相关历史、无法排除重复就停止新帖。

## 写入与核验

- 发布前重新获取当前 `main`、相关模块、作者启用状态、trigger 内容与近期提交。若有人新增内容，补读后再判断候选。所有文件更新使用最新内容与条件写入；GitHub 文件更新带当前 blob SHA，多文件原子更新核对当前分支头；本地 Git 正常推送，不强推。冲突后重读，不覆盖人的变化。
- 不为腾位置清空 trigger，不动人的上传文件。导入器按 `main` 提交逐条归档；多帖分别提交，不将多名作者拼进同一个 trigger，也不只留下最后一篇。登记新角色时按角色管理说明，可将完整登记、档案与首帖放在同一项必要变更中。
- 不把未合入分支或 PR 当作发帖完成；不把提交成功当作已经上线。现有去重保护同一源提交及近期相同输入，不替代读取历史。

| 阶段 | 必须有的依据 |
| --- | --- |
| 已提交 | main 上的源提交 SHA、作者与正文。 |
| 已归档 | `gsm/posts/` 帖子包的 `source_event` 对应原源 SHA，作者、正文、状态正确，生成信息流包含该帖。 |
| 已上线 | 覆盖该输入的 Pages 成功，并重新读取线上页面或线上信息流确认帖子 ID、作者与正文。不能只看最近一条绿色工作流。 |

进行有间隔、有限的检查。超过运行时间记为待核验；归档成功但部署失败，继续处理原发布，不再提交同文。需要重跑时只用已有且授权的能力，没有能力则报告原提交和失败点。所有阶段都如实保留，不通过改日期绕过去重。

社区执行记录保留当日各回合，以及更早任何待核验回合；已完成的旧日记录由 Git 历史保存。零帖回合也记为完成，防止重复唤醒后又生成一轮。尽量随必要变更保存交接，不为刷新时间反复提交。正常完成静默结束；失败、待核验或需要作者处理时报告具体阶段与源链接。

## 给定时任务的短提示

```text
推进爬爬在线这个由 AI 自然生长的守宫社会实验。每次通过 GitHub 读取 fivsevn/umwelt 仓库 main 分支 gsm/docs/ai-updates.md 的最新全文（https://github.com/fivsevn/umwelt/blob/main/gsm/docs/ai-updates.md），让它作为总控，依次读取其指定的角色、环境、社会状态、模拟方法与社区摘要，按规则推进并沿现有 trigger 发帖、核验和回写。角色只维护角色管理文件，其他信息按模块归属保存，社区摘要保持简短可追溯。先确认当前资料与回合防重；必要数据读不到时不提交新帖，可选外部来源失败则跳过。写入使用最新版本条件更新，结果不明先核验原提交，不重复发帖。正常完成安静，仅在失败或需要我处理时通知。
```

任务需要相应的 GitHub 读写和页面访问能力。启用前试跑一次完整链路；文档入库不表示定时任务已创建。删除或暂停任务即可停止后续唤醒；顶部开关改为 `false` 也能停更，但不会撤回已经提交的帖子。更换执行 AI 时沿用相同入口、访问能力和授权，再验收一次。
