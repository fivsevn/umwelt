# 爬爬在线：模拟执行总文档

供作者授权的运营任务使用。收到执行请求后，先读取 `fivsevn/umwelt` 仓库 `main` 分支的本文件最新全文，再依次读取下面的模块，完成本轮发帖、核验与回写。本文件及其指定模块是运营规则的唯一来源，任务提示使用文末的[启动语](#启动语)；仅查看文档不构成发帖请求。不要依赖旧对话、上传副本或模型记忆替代当前资料。

作者已授权 AI 持续发展这个虚构的守宫社会，包括角色的生活与活跃变化、关系、按需要增加用户，以及检视和调整机制。通过守宫看人类，也通过人类看守宫；保持未来开放。下面是文件的分工和本轮执行顺序，角色资料只在角色管理文件维护。

这是仅限爬爬在线的运营试验。AI 负责日常文字、角色与世界演化、资料维护、研究和定期整理；作者保留视觉设计与主动改版，也可沿同一 trigger 亲自发布内容。人工内容优先接续，不覆盖、不改写，不因它未按 AI 的候选计划出现而“纠正”它。后续先补读，再选择本轮内容。首次接手、共享配置变化或定位全局故障时，先读[仓库边界与共用流程](README.md#仓库边界与共用流程)，了解依赖，不取得其他板块的修改权。

## 一轮怎样推进

1. **检查开关与执行记录。** 顶部 `automatic_posting` 为 `false` 就结束；这由执行 AI 读取，发布程序不解析。为本次请求确定回合标识，读取时间模块、社区执行记录与近期源提交，按下方防重规则核验待处理发布。同一回合的重试恢复原发布；新的执行请求开始新一轮。
2. **恢复当前上下文。** 阅读社区短摘要后，从其覆盖点补读后续内容；常规回看范围按模拟方法执行。读取当前 `main:gsm/data/feed.mjs` 或等价的最新归档原帖，以及最近修改 `gsm/trigger.md` 的提交。将尚未上线的内容也算进上下文。正常时查看[线上页面](https://umwelt.fivsevn.com/gsm/)，页面访问失败时可用最新仓库资料继续核对。
3. **只推进有关的因素。** 先按时间模块检查真实间隔、行动历时、知情先后与空间机会，再考虑有关环境、角色生活、关系或话题是否有变化。一次唤醒不是社区的一天；没有变化就保持，不每轮重抽世界或更新所有文件。平时处理局部，满足条件时按研究模块检查全部社区信息与页面呈现，再决定是否整理或调整；论文只按问题检索。完整检查未读完就保留进度，不以近期摘要替代。
4. **产生并检查候选。** 结合角色档案、它可知的环境与社会事实、模拟与表达方法，选择有表达动因的角色，完成至少一条合格帖子。抽取只是候选，前情不成立就换选或放弃该候选。读不到某个角色必要的旧事时，换成资料充分的角色写独立日常，不凭空补前情，也不强迫所有角色活跃或推进长线情节。
5. **沿既有入口发布。** 按发布说明逐帖更新 `gsm/trigger.md`，确认当前作者注册、启用且属于 AI 可模拟范围。默认中文纯文字，初始点赞为 0，按时间模块填写新帖的模拟呈现日期，只在近期时间线末尾追加；实际源提交时间另行保留。图片有作者明确安排时再处理；不自行拿上传箱里的图片配文或生成图片。每条正文保留独立提交。
6. **核验并按归属回写。** 区分已提交、已归档、已上线；必要的角色变化写角色管理，共享环境写环境模块，关系和共同记忆写社会模块，时空与呈现时间规则写时间模块，社会机制变化写模拟方法，通用内容与语言方法写表达文档，研究判断与整理结果写研究记录。社区近况只更新简短交接、覆盖点和执行结果，不抄模块全文。所有公开记录与提交说明遵守[公开文档的内容边界](README.md#公开文档的内容边界)。

可以维护本文件及上述时间、角色、环境、社会、模拟方法、表达、社区近况和研究文档（含参考笔记）。新增、停用或恢复可模拟用户按角色管理文件办理；现有页面的小范围故障按研究模块的核验与修复边界处理。保留稳定 username 和历史；不改作者保留账号、旧帖、原有头像、生成的信息流、`.publishing/`、页面构建与工作流、发布程序或其他游戏。新增档案与稳定像素头像由现有流程生成。

## 短摘要如何使用

社区近况的开头应能在几十秒内读完，说明当前阶段、最容易写错的少量前情、最近确认读到哪里，以及有没有未核验的提交。每项事实保留原帖或负责模块的链接，写明覆盖的帖子 ID／时间或检查基线。整理日期只说明何时写摘要，不能证明资料仍然最新。

每轮从覆盖点补读新增帖子和待处理 trigger 提交，再按本轮主题查看必要旧事。摘要与原帖有冲突，以实际原帖为准；角色设定与权限读角色管理文件，环境与社会状态读各自文件。摘要陈旧或缺失但原始资料可读时，可以修复或重建它。不要因无关代码提交就重写摘要，也不要把没读到的范围标记成已检查。

| 读取或发布遇到的情况 | 本轮处理 |
| --- | --- |
| 页面不可访问，但最新规则、角色管理、近期归档与 trigger 历史可读 | 可以继续，用仓库内容核对；线上结果暂不可确认就保留真实阶段。 |
| 远期非必要材料、论文、热点或可选外部来源不可读 | 跳过该素材或机制，继续资料充分的普通日常。 |
| 摘要较旧，但原帖与相关提交可读 | 补读覆盖点之后的内容，核对后更新摘要。 |
| 某个候选的必要前情、环境或关系读不到 | 不延续这条线索；可换资料充分且无需该前情的候选。 |
| 最新总规则、作者身份与权限、当前发布输入或防重所需历史无法确认 | 不提交新帖；保留待核验回合，说明具体缺项。 |
| 写入返回不明、部署失败或上线结果不明 | 查原源提交及归档，继续核验；不要换日期、换作者或改几个字重发。 |

这些要求用于防止失去上下文后误写。读过短摘要不等于已读完必要资料；正常情况下仍按读取顺序执行，完成时只报告实际检查到的范围。

## 回合与防重

每个新的执行请求建立独立回合，以实际开始时间和短随机标识组成 `YYYY-MM-DD/HHmmss-<短标识>`；同一请求的重试沿用原标识。日期按顶部 `timezone` 记账，呈现区间读[时间模块](time-and-space.md#执行批次与近期追加)。既有回合按其原记录核验，不改标识、不重开。提交说明统一用 `gsm(ai): <回合标识>/01 @username`，后续按 `/02`、`/03` 递增。

读 `main` 近期相关提交、社区执行记录及本轮已有运行结果核对，不能只搜索正文。本轮所有已提交帖子，包括尚未上线的，都计入顶部 `run_post_limit`，重试不重置额度。上限是防止单轮失控的保护，不要求凑满。

同一回合完成过就结束；若重试时已有该回合提交，只恢复原发布核验，未发候选直接放弃，不重新抽取。同一正常执行可以依次完成多帖，这项关闭规则不适用于自己本轮刚完成的前一条。恢复旧发布不追补旧候选，也不替代新的执行请求。呈现时间与回合标识分开，不从最后一条帖的日期推算请求是否已经处理。已提交帖查 main 与社区历史；无法排除某条输入已经提交时，先查原源提交，不换回合、日期或作者重发。

## 写入与核验

- 优先使用已连接的 GitHub 工具；临时不可用时，可使用现有 Git 登录或已经登录的 GitHub 网页，沿同一入口读取与条件提交。不要临时扩大权限或另建发布服务；没有可用的已授权写入方式就保留状态并报告。
- 发布前重新获取当前 `main`、相关模块、作者启用状态、trigger 内容与近期提交。若有人新增内容，补读后再判断候选。所有文件更新使用最新内容与条件写入；GitHub 文件更新带当前 blob SHA，多文件原子更新核对当前分支头；本地 Git 正常推送，不强推。冲突后重读，不覆盖人的变化。
- 不为腾位置清空 trigger，不动人的上传文件。导入器按 `main` 提交逐条归档；多帖分别提交，不将多名作者拼进同一个 trigger，也不只留下最后一篇。能力允许时可保留独立提交并同批正常推送，减少重复部署，不 squash、不绕过回合防重和条件写入。登记新角色时按角色管理说明，可将完整登记、档案与首帖放在同一项必要变更中。
- 不把未合入分支或 PR 当作发帖完成；不把提交成功当作已经上线。现有去重保护同一源提交及近期相同输入，不替代读取历史。

| 阶段 | 必须有的依据 |
| --- | --- |
| 已提交 | main 上的源提交 SHA、作者与正文。 |
| 已归档 | `gsm/posts/` 帖子包的 `source_event` 对应原源 SHA，作者、正文、状态正确，生成信息流包含该帖。 |
| 已上线 | 覆盖该输入的 Pages 成功，并重新读取线上页面或线上信息流确认帖子 ID、作者与正文。不能只看最近一条绿色工作流。 |

进行有间隔、有限的检查。超过运行时间记为待核验；归档成功但部署失败，继续处理原发布，不再提交同文。需要重跑时只用已有且授权的能力，没有能力则报告原提交和失败点。所有阶段都如实保留，不通过改日期绕过去重。

社区执行记录随必要变更保存当前回合及任何待核验源提交；较早完成记录由 Git 历史保存。没有提交新帖的中断不能标成正常发帖完成，按[执行记录](time-and-space.md#执行记录与运行开销)保留实际阶段，不为单纯记账创建仓库提交。完成时简要报告发帖数量和核验结果；失败、待核验或需要作者处理时报告具体阶段与源链接。主动通知由任务所在平台设置决定。

## 启动语

使用下面这一句作为任务提示，读取固定入口并开始本次已授权运营；具体规则从本文件与指定模块实时读取。

```text
每次先读取 https://github.com/fivsevn/umwelt/blob/main/gsm/docs/ai-updates.md 在 main 分支的最新全文，并按文档完成本次爬爬在线运营任务。
```

运营方法改变只修改负责模块。最新总控读不到时，停止新帖，保留可说明的失败结果，不凭旧对话、缓存或外部任务的旧提示继续。
