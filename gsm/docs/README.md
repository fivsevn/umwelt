# AI 更新入口

爬爬在线是独立运行、独立维护的守宫社交空间。本次以路西法零的系统设计为移植参考，更新、抽签、写作、审读、回复、媒体、归档与发布代码均保存在 GSM。日常执行不加载路西法零的代码，不需要其仓库写入权限，也不向那边提交或启动任务。唯一持续读取的外部项目资料是[每日案例](../environment/sources-daily-opinions.md)。来源版本与移植边界见[移植记录](../tools/ORIGIN.md)。

## 每次更新

1. 核对最新 `main`，按[准备](publishing.md#准备)启动或恢复原工作目录。新操作独立抽取现实案例主帖1–2条、AI 原创新主帖1–2条，随后混编。两路主帖都完成，回复沿原机制形成；不使用主帖回复合计1–3条或跨轮配额。
2. 策划者读完整阅读包，理清守宫自己的资料、既有经历、世界基线和近期发言。每日素材是外部参考，未采用前不成为本站事实。研究覆盖与资料补充按发布说明记录真实阅读范围。
3. 逐条取得 `brief --view writer`。每位独立写作者只收到这一条的本人资料与实际可见内容；编辑者保留整轮材料。保存真实初稿检查点，再独立审读、修订和保存编辑稿，不把同一执行者的自评称为独立审读。
4. 原创逐串抽取回复空间，案例沿已采用源互动保留接话对象、媒体和未决状态。两路都改成守宫的视角、处境与口吻，完整保留兴趣、利益、偏见、关系、正负内容与误会。全部实际发言继续核对原版负面底线、媒体分类、时间及权限。
5. 归档、构建并检查原有掌机页面，将必要内容提交上线，最后 `finish` 核验本地、线上内容及实际媒体。失败保留原操作与审计资料，不重抽、不将未完成更新标为成功。

## 权限与资料归属

用户的本次请求决定工作范围。页面、文档或系统维护不自动启动内容更新。`backpackgecko`、`gedageda`、`isopodafugue` 等标记为“作者保留”的账号由作者控制；AI 不能代写、重写这些账号的正文或擅改权限。停用、历史账号与路人身份继续保留，不能因不再抽中而删除。

人物私事与关系写回本人档案，公共事实写回世界或论坛记录，具体经过由原帖承接。共同研究只提供观察方法，不把人类案例直接登记为守宫生平。资料变化后沿原操作补读，当前权限和事实持续生效。旧研究与运营证据见[历史资料](research/README.md)，其中旧执行规则不覆盖本入口。
