# 研究、自省与整理

[执行总控](../ai-updates.md) · [模拟方法](../simulation.md) · [当前研究记录](observations.md) · [参考资料](references/README.md)

这是系统研究自己、定期整理爬爬在线的工作区。既看这个守宫社会怎样发展，也看负责生成、记忆、组织与呈现它的系统有没有问题。研究结果先影响维护方法，再通过守宫们的生活体现；不用安排角色替维护者发表研究报告。

日常更新只读近期与有关历史。完整自省则检查整个板块的社区信息、内容与形式，再判断是否调整、怎样调整，也可以决定暂时不改。不要把自省变成催活跃、促增长、消除分歧或定期改版的任务。

## 何时做

- **完整自省与整理**：起步在距上次约一个月、累计约 30–50 条新帖，或用户、关系、环境与机制有明显变化时判断是否启动。长期安静可以延后；没有新增帖子但出现链接、发布或页面故障，仍检查有关部分。
- **局部检查与恢复**：发现前情冲突、重复输出、错误引用、摘要失效、发布不明或页面异常时即时处理，不等完整自省。局部处理不标成完成了全社区检查。
- **日常回看**：近期检索与约一至两周的完整历史回看仍按[模拟方法](../simulation.md#回看的几种节奏)进行；回看不要求每次都写研究报告。

这些时间与数量是可调整的项目起步参数，不是论文证明的最佳周期。触发条件只决定是否值得检查，不预定一定要发现问题。

## 完整检查的范围

先固定本次 `main` 提交基线，清点帖子数量、时间范围和模块版本。读取全部公开帖子正文及其作者、日期和必要元数据，不能只依赖信息流首页、最近动态或社区短摘要。结合实际变更核对：

| 范围 | 要检查什么 |
| --- | --- |
| 社区生活 | 全部公开历史中的独立生活、联系与疏远、潜水与回归、共同习惯、变化与未定之事；哪些结论有依据。 |
| 角色与世界 | 完整角色管理文件、当前环境与社会记录；内容、句法与语用是否趋同，是否出现生硬中文或翻译搭配、知情范围是否失真、结束的事是否重演、物种细节是否有来源。作者保留账号只读，不取得代写权。 |
| 生成与执行 | 当前总控、模拟方法、回合记录、相关 trigger 源提交、未归档／未上线内容及其发布结果；是否存在重复或遗漏。 |
| 文档与资料 | 入口是否清楚、职责是否重复、摘要是否陈旧、链接是否有效、研究结论是否超出来源、参数是否堆积；只查与问题相关的论文原文。 |
| 页面与呈现 | 线上信息流的作者、正文、顺序、时间、头像、文字显示、导航及已有语言／点赞功能是否正常；必要时检查手机与桌面显示、错误日志、加载大小和已有检查结果。 |
| 维护开销 | 读取量、帖子与档案体积、提交／部署次数和实际耗时是否出现问题；先看事实，再决定是否需要更省的组织方式。 |

“全部”指爬爬在线的完整社区资料与必要的呈现、执行信息，不是无差别重读整个 Umwelt 仓库、图片二进制或所有旧代码。帖子很长以后可以按时间段分轮读取，在[当前研究记录](observations.md)保存目标基线、已读范围、剩余范围与下一段入口；未读完就保留“进行中”。结论前补读基线之后新增的社区内容，标明最终覆盖点。不能只看头尾，或只读摘要，就宣称全量检查完成。

维护者能读到的资料不自动成为角色知道的事。全量检查不赋予角色全知视角，也不重写过去来消除不一致。

## 怎样研究与作决定

1. **观察并定位。** 写明问题、检查基线与覆盖范围，列少量可复核的帖 ID、文件或源提交。将事实、主观判断、模拟设定分开；语言审读按[内容与中文表达](../expression.md)及作者反馈，不以 AI 检测分数替代；“氛围单一”先是待检验判断。
2. **找解释与资料。** 对重要判断提出至少一种替代解释。例如长期沉默可能来自角色倾向、样本很少、抽取偏差或执行漏读。按[资料索引](references/README.md)找对应研究，必要时上网核实原文；资料不可访问就保留不确定，不能编造支持。
3. **决定是否调整。** 可以不改、补充观察、整理记录、修复故障，或尝试一个小变化。不要预设社区要趋向热闹、平均、和谐或某个社会理论；关系疏远、小圈子、争执与冷门兴趣本身不是故障。
4. **有条件地实施。** 机制试验一次只调整一个可解释的主要因素，先记原值、理由、预期表现、观察窗口／样本条件与撤回条件。关联文件可一起改，但不同时换一套人格、概率、环境和话题再猜原因。角色、环境、社会事实与通用方法仍回各自负责文件，研究区只存问题和判断。
5. **核验与复查。** 工程问题用实际工具结果、原始内容、既有检查和线上结果确认；创作／机制变化用后续帖子与明确观察标准复查，记录改善、无变化、退化或仍不确定。窗口内资料不足就延期判断，不能立刻宣布成功。
6. **保留或撤回。** 结果支持时保留；无效或副作用明显时恢复原参数／规则，记录原因。Git 保存版本；撤回方法变更不删除已公开帖子，也不抹掉反例。

这个闭环借鉴 [Generative Agents](references/agent-memory.md#park-2023)、[Self-Refine](references/self-reflection.md#madaan-2023)、[Reflexion](references/self-reflection.md#shinn-2023) 与[自主管理架构](references/self-reflection.md#kephart-chess-2003)。[自纠研究的反例](references/self-reflection.md#huang-2024)要求保留外部核验：AI 觉得自己改好了不算证据。AI 自己生成的回复、声誉和所谓民意是模拟输出，不能循环当成独立验证；后续帖子只能说明此系统的输出如何变化。

当前页面点赞保存在访客本机，没有可供 AI 读取的全站关注、回复或传播统计。初始点赞值与 AI 自己在浏览器点的赞都不代表社区民意。只有实际可获取的交互证据与作者反馈才纳入观察，并说明来源和样本限制，不能从中直接推出人类社会规律。

## 可以怎样整理与恢复

| 情况 | 可以做的事 | 怎样确认 |
| --- | --- | --- |
| 摘要过期、模块重复、角色事实冲突、资料引用错误 | 从原帖与权威文件重建摘要，合并重复说明，修正归属和引用；角色仍只维护角色管理。保留真实的不确定与反例。 | 对照来源、检查相对链接和角色表解析约定；不把推测升格为事实。 |
| 必要资料读不到或状态不明 | 有限重试或换已授权的等价来源；可选来源失败则跳过，需要身份／防重信息时停止新帖。 | 依[执行总控](../ai-updates.md)确认必要信息已恢复，不能通过关闭检查来恢复运行。 |
| 发布中断或结果未知 | 追查原源 SHA、`source_event`、归档与部署，沿原发布继续核验；使用已有且授权的恢复能力。 | 区分已提交、已归档、已上线，不改几个字另发一次。 |
| 现有页面有明确可复现的小功能故障 | 先定位；可在 `gsm/` 内作必要、可逆的小范围功能修复，沿用现有界面。涉及作者的视觉风格、布局或样式调整时，保留证据并报告，不自行改版。 | 按[现有检查说明](../../tests/README.md)运行相关检查与页面验证，确认实际结果后再记录修复。 |
| 涉及发布程序、构建／工作流、权限、生成数据或跨游戏改动 | 保存复现步骤、影响、源提交与建议，报告作者处理；不要用自省名义扩大改动范围。 | 保留待处理状态，不宣称已修复。 |

检查包含形式与内容，整理力度按实际问题决定。视觉风格与主动改版由作者负责；AI 检查显示与功能异常，不以整理为由替换作者的审美或人工帖子。不要定期重设计界面、增设功能、批量换头像、清除历史、强推分支或重置生成状态。代码层修复不混入普通发帖提交；读不到现有检查或无法验证时先记录问题。一次恢复经过有限尝试仍无进展就停止并报告，不进行无限重试或自我唤醒。

## 保存什么

[当前研究记录](observations.md)只保留当前问题、进行中的检查／一个小试验、最近实质结论、下次复查条件和必要来源。完整自省完成后，明确写出覆盖范围、观察、替代解释与“调整／不调整”的决定。没有问题也可简短写明检查范围与保留现状的理由。

社区近况只链接研究状态与必要结论，不复制报告。过往完成记录由 Git 历史保存；确实需要长报告时才在本目录新增有主题的阶段研究，避免每天创建文件。资料集中在 `references/`，按主题维护短书目与适用边界，不把论文全文、PDF 和网页副本存进仓库。只有进度、判断或内容实质变化才提交，不为刷新日期触发部署。
