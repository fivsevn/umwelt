# 发帖与用户管理

发帖有两个入口：[`trigger.md`](../trigger.md) 写文字或图文；[`uploads/`](../uploads/) 直接上传图片。提交到 Umwelt 仓库的 `main` 后自动归档、转换 WebP、发布并核验。每条帖子始终拥有自己的文件包，修改旧帖直接改那个包。

## 只上传图片

把 JPG/JPEG、PNG、WebP、GIF、HEIC/HEIF 放进 `gsm/uploads/`，提交即可，不需要编辑 trigger 或手写图片引用。

- 不写内容：发布纯图片帖。一次上传多张时，每张一帖。
- 要配文：写在提交的详细说明中；没有详细说明时也接受自定义提交标题。`Add files via upload` 等默认标题不会出现在帖子里。
- 未指定用户：从启用且允许随机分配的用户中选择。**选择结果会永久写入帖子包**，刷新、重新构建、增加用户、修改随机开关都不会给旧帖换作者。
- 图片单独上传时，不继承 trigger 中上一次的正文、作者、日期或点赞数。
- 想指定用户或点赞数，可以在提交的详细说明里写配置和配文：

```text
---
username: backpackgecko
likes: 24
---

出游了。
```

原图在发布成功并核验页面、WebP 文件之后自动从 `uploads/` 清理。失败时保留；若同名文件已经换成新图，也保留新图。原始提交可从 Git 历史找回；旧帖只使用自己包里的转换件，不依赖上传目录。删除上传原图的清理提交不会再次发帖。

这沿用 [Flux 图片入口](https://github.com/fivsevn/fivsevn-flux/blob/main/trigger_imgs/README.md) 的上传、配文、WebP 归档和上线后清理方式，额外加入了角色分配；这里不读写 Flux 的帖子。

## 文字或图文

修改 [`gsm/trigger.md`](../trigger.md)，和配图一起提交：

```yaml
---
username: backpackgecko
name: ""
status: published
likes: 24
date: ""
---

今天换了个位置。

![窗边](uploads/window.jpg)
```

也可以删去配置区，直接写正文，此时使用随机用户、提交时间和 0 个初始点赞。

| 字段 | 填法 |
| --- | --- |
| `username` | 留空随机；已注册用户只需填写其账户名，不写 `@`。只接受 1–32 位英文字母和数字，统一小写。数字开头或全数字的账户名建议加引号。 |
| `name` | 新用户名同时填写昵称时自动建档，默认不参加随机分配。已有用户的名字在用户档案里修改。没有足够信息确定用户时使用随机池。 |
| `status` | `published` 公开、`draft` 草稿、`hidden` 隐藏。 |
| `likes` | 初始点赞数，非负整数，默认 0。访客在自己设备上的点赞在此基础上加 1。 |
| `date` | 留空为提交时间；也可填写带时区的时间，例如 `"2026-10-19T14:00:00+08:00"`，用于排序，不是定时发布。 |

正文中的图片按所写位置显示，一条帖可放多张。若同次修改 trigger 正文并上传图片，但未写任何图片引用，自动把本次图片附在正文后，组成一条帖。明确引用过的图片不会再单独发布；同次上传但未被引用的其他图片各自发帖。

trigger 没有正文时不发空帖；如果同次上传图片，配置可用于这些图片。仅改注释、添加默认 `likes: 0`、或原样重跑不会重复发帖。再次发同样文字可更新 `date`。只上传图片时不必清空旧 trigger。

图片自动转 WebP：照片质量 85，PNG/GIF 无损，保留透明和动画；已有 WebP 校验后直接使用。损坏图片会停止发布；替换或删除后可以重试，已被替换的损坏版本不会发出。

## 用 Markdown 管理所有用户

[打开用户管理表](../users/README.md)。这份 Markdown 就是管理入口，**可以直接编辑，不是生成文件**。提交后 Actions 自动创建或更新对应用户文件夹。

新增用户只需要在表格末尾增加一行：

```text
| newgecko7 | 新角色的昵称 | 是 | 是 | |
```

五列依次是：`username`、昵称、启用、可随机分配、头像原图。最后一列可以留空。

- 随机用户转固定角色：将“可随机分配”改为“否”，其他不变。旧帖作者不会重抽。
- 暂停用户：将“启用”改为“否”。历史继续显示，随机与指定的新帖都停止；改回“是”即可恢复。
- 删除用户：直接删去该行；没有历史帖子的用户文件夹会自动清理。有历史帖子的用户请停用，误删会在发布前提示恢复，保留过去的身份。
- 改昵称：只改表格里的昵称。已有历史之后不要直接修改 username，因为它是角色的固定身份。
- 新 username 只用小写英文字母和数字，不写 `@`。在 trigger 同时填写新用户名和昵称，也会自动追加到本表，默认不参加随机分配。

未设置头像时，用户文件夹只放自动同步的档案，不放头像文件：

```text
gsm/users/newgecko7/
  profile.json        由管理表自动创建和更新
```

发帖时，按用户名生成一张稳定的随机像素头像；运行输出位于 `gsm/assets/avatars/`。刷新、重建、转成固定角色都不会换脸。

需要自定义头像时，把原图放进该用户文件夹，再在表格最后一列填写文件名，例如 `avatar-source.png`。原图与用户档案放在一起，生成的网页头像仍统一 WebP。背包宫的照片已移入 `users/backpackgecko/`，完整保留原图，使用原有裁剪和 48 × 48 降采样。

裁剪等高级设置可在该用户的 `profile.json` 中修改：`avatar_pixels` 为降采样尺寸；`avatar_crop` 为原图像素坐标 `[左, 上, 右, 下]`。昵称、启用、随机开关、头像文件名以 Markdown 管理表为准，Actions 同步时保留这些高级设置。用户表的空头像栏对应 `avatar_source: ""`，不需要上传占位图片。

## 直接修改旧帖

```text
gsm/posts/2026/10/帖子编号/
  index.md          作者、时间、点赞与中文正文
  index.en.md       可选英文正文
  index.ja.md       可选日文正文
  assets/          本帖自己的 WebP 图片
```

`username` 是当时确定的作者，随机身份也会存成明确的用户名。`author_assignment` 仅记录首次分配方式，不控制后续重分配。修改旧帖的 `likes` 可调整初始点赞数；编辑内容时保持 `id`，让已有点赞记录继续对应。作者昵称和头像由用户档案统一管理。缺少翻译时显示原文，不必填写三遍。

## 本地操作与发布检查

首次安装：`python3 -m pip install -r gsm/tools/requirements.txt`。

- `python3 gsm/tools/publish.py publish`：导入当前 trigger 与新上传图片，预览本地页面。
- `python3 gsm/tools/publish.py build`：读取管理表、同步用户并重建旧帖，不发新帖。
- `python3 gsm/tools/publish.py watch`：保存后自动更新本地内容。
- `python3 gsm/tools/publish.py ingest`：CI 按提交逐条归档，重复执行不再发一次。

本地预览不清理上传原图。线上完成浏览器检查、部署和逐文件核验后才执行清理；中途出现新提交则推迟清理，保护新上传文件。归档包、用户档案和导入位置一起保存。

`data/feed.mjs`、`assets/avatars/`、用户文件夹内的 `profile.json` 基本字段、`.publishing/public.json` 是生成内容；`.publishing/state.json` 记录处理位置，请勿手改。源配置、原图、草稿不会进入网页发布包，但仓库是公开的，可以在 GitHub 查看。
