# 验证与发布

本页维护全仓库静态站点的发布约定。游戏专项检查见[测试导航](../tests/README.md)，原生桌面打包见[桌面说明](../mac/README.md)。Windows 流程在推送时可以构建和检查，上传到 GitHub Release 仅在手动启动该流程时执行；文档与仓库整理不更新 Release。

## 发布边界

[Pages 工作流](../.github/workflows/pages.yml)依次执行结构检查、准备站点、字体子集、资源版本标记和成品浏览器检查，通过后上传并部署。推送 `main` 会触发；仅含 `README*.md` 的推送被忽略，其他开发文档变更仍可能触发部署。

[prepare-site.mjs](../.github/scripts/prepare-site.mjs)只复制 Git 跟踪且通过 `publicFile()` 筛选的文件，并为 HTML 的直接模块依赖加入 modulepreload。它排除根 `MAINTENANCE.md`、`docs/`、`tests/`、`tools/`、`mac/`、任意游戏目录下的 `docs/`、`tests/`、`art/`、`tools/`、`dev/`、仓库管理文件及各目录的 README / AGENTS。未跟踪的本地实验不进入发布包。新增游戏沿用这些目录边界；运行资源放在游戏根目录或 `assets/` 等运行目录。`shared/` 为跨游戏运行模块，随站点发布。

Markdown 的用途由读取方决定：`isopoda/credits*.md` 是游戏内容，字体许可也随资源保留。各游戏 `art/`、`tests/` 中的原稿与检查页可随仓库保存，但不进入网页发布目录。

## 字体与资源版本

源码 HTML、CSS 和模块路径不手写 `?v=` 计数器。发布时先完成字体子集，再对临时发布目录运行：

```sh
node .github/scripts/stamp-assets.mjs /path/to/prepared-site "$GITHUB_SHA"
```

版本标记使用完整提交 SHA，统一处理 HTML 本地资源、JS 模块导入和静态文件名、CSS URL，以及 Credits 的已有文件名表。原有相对路径、非 `v` 参数、片段、导航地址与远程 / data URL 保留；缺失的明确相对资源会使检查失败。只对发布副本运行，不对源码目录盖章。

转换可重复运行且结果一致，不引入运行时打包器、路径重命名、Service Worker 或存档迁移。回滚旧提交时按该提交重建发布包；已经打开的页面沿用已载入的模块，刷新后读取对应的新资源版本。

字体子集保留旧 MORNING 文本专有的 `凝吃址铺`，使历史存档文字仍有字形。删除运行文本时不能顺带缩减旧存档所需字符。

## 成品检查与发布状态

`tests/browser/published-artifact.cjs` 必须访问已经完成准备、字体子集和 SHA 标记的发布目录。当前检查主页、三个信号、体温调节、等足目赋格及两个实验室、南北阳台、车库和房间，共 10 个入口；Chromium / WebKit 各检查桌面和手机宽度，共 40 组。它核对资源、页面控件、运行错误与版本标记；专项剧情、编辑及原稿检查仍按各游戏指南执行。

```sh
BASE_URL=http://127.0.0.1:8794 EXPECTED_SHA="$GITHUB_SHA" node tests/browser/published-artifact.cjs
```

需事先从发布目录启动 8794 服务并准备 Playwright 浏览器。CI 当前使用 Playwright 1.62.1 及同版本预装镜像；浏览器成品关卡上限为 18 分钟，失败则停止上传和部署。依赖版本、超时及入口数量以工作流和脚本为准。

成品检查为花农时代实时天气请求提供固定响应，核对全屏游戏显示区域经纬度与可读天气，电视模式使用虚构读数，并验证 4:3 画面、完整三行记录及模式切换后控件归位；发布不依赖第三方天气服务当时是否可用。缓存、超时和模拟回退由天气单元测试覆盖，正式页面继续请求真实天气。

本地通过只说明当前检查通过。线上状态须核对对应提交的 Pages 工作流和实际页面；原稿保存、运行资源导出、提交与线上发布分别记录。

## 文档与目录整理验证

文档、原稿和测试路径变化时，同步引用、检查命令、工作流与发布排除规则。运行文件中的来源路径或开发预览判断也可能需要跟随更新；逐项确认这些差异，并保护游戏素材、存档和公开页面行为。

1. 固定整理前的提交作为 baseline，核对 diff 仅包含预期开发文档、原稿和测试的归档，以及必要的工具、工作流与发布排除规则调整。
2. 用 `.github/scripts/prepare-site.mjs` 分别从 baseline 与工作树准备仓库外的全新发布目录。文件清单来自 `git ls-files`；新增、移动或删除的文档须纳入待发布清单，可使用独立临时 Git 索引，避免更改工作区的暂存状态。
3. 比较两个发布目录的全部路径与每个文件的字节，包括隐藏文件。完全相同才能认定发布输入未变；不一致时先查清原因，涉及运行文件则补充相应浏览器回归。
4. 运行 `node tools/check-all.mjs`；另行检查文档相对链接、页内锚点、文件路径与命令入口。结构检查不包含完整文档链接扫描。无需为纯文档变更新增镜像式测试。

比较发生在字体子集和 SHA 标记前。后续只有使用相同工具及版本标记才能比较最终字节；不同提交部署时资源 URL 的 SHA 正常变化，不代表画面或行为发生变化。
