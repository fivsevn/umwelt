# 目录归属与新增游戏

[共用文档](README.md) · [名称规则](naming.md) · [维护总入口](../MAINTENANCE.md)

## 根目录的职责

| 位置 | 保存内容 |
| --- | --- |
| 根 HTML、CSS、JS | UMWELT 桌面、图标与共享窗口外观 |
| `shared/` | 跨游戏的运行时规则，包括游戏标题登记表 |
| `assets/` | 多个页面共同使用的音频、字体及其许可 |
| `docs/` | 命名、目录结构、共用音频、发布约定、跨游戏维护记录 |
| `tests/` | 桌面、跨游戏语言与音频、发布包的检查 |
| `tools/` | 全仓库检查入口和公共页面检查 |
| `mac/` | 现有 macOS / Windows 共用桌面包装、原生窗口与打包检查；Windows 构建在 `mac/windows/` |
| `.github/` | GitHub 要求放在此处的工作流与发布工具，按职责调用各游戏的检查 |
| `<game>/` | 对应游戏的全部专属运行内容、文档、原稿和测试 |

内容归属以实际使用者为准。单个游戏的素材、数据、文档、工具、测试及样本放回该游戏；跨游戏使用的模块和集成检查留在共用目录。桌面图标与首页导航由整体桌面维护。跨游戏的历史报告作为完整记录保留。

## 游戏目录的统一结构

```text
<game>/
  README.md          游戏维护入口
  index.html         公开游戏主页
  assets/            游戏实际读取的素材与素材许可
  data/              游戏数据与来源登记（需要时）
  locales/           翻译（需要时）
  docs/
    README.md        文档导航
    maintenance.md   内容与实现的维护约定
    reference/       有日期的研究、设计与验证记录（需要时）
  tests/
    README.md        命令、覆盖范围、环境与前置条件
    *.test.mjs       Node 检查
    browser/        浏览器检查与固定测试页
    native/         只针对该游戏的原生桌面检查（需要时）
    fixtures/       测试样本（需要时）
    support/        测试辅助（需要时）
  art/               可编辑原稿、制作工具及原稿检查（需要时）
  tools/             游戏专用数据和内容检查（需要时）
  dev/               本地开发预览（需要时）
```

仅建立实际有内容的目录。运行模块可以留在游戏根目录，也可以按渲染、互动或子页面分组；现有公开页面和存档标识保持稳定。依赖单个游戏的第三方组件随该游戏保存，并保留自己的许可。

原稿保存在 `art/`，游戏读取的导出物保存在 `assets/`。测试截图和临时发布包默认输出到仓库外；需要长期保留的验证记录按其所属游戏归档。

## README 格式

各项目 README 使用相同顺序：名称与标识、游戏入口、本地运行、目录与文档、内容维护、检查。首段说明游戏内容，导航连接共用规则、游戏文档和测试说明。

新游戏从[游戏 README 模板](templates/game-readme.md)填写。README 提供稳定入口；详细命令、研究资料、内容规则写入对应正文后链接过去，避免重复维护。

## 新增游戏

1. 选择小写目录标识、固定程序文件名和中英日可读标题，在 [`shared/games.mjs`](../shared/games.mjs)登记，并更新[名称表](naming.md)。
2. 建立游戏主页、README、`docs/README.md` 和 `tests/README.md`；按实际需要添加其他目录。
3. 将专属资产、翻译、原稿和检查放入游戏目录；共享模块通过相对路径引用。
4. 在桌面增加图标和链接，保持 HTML 初始标题、三语根 README、游戏 README 与共享登记一致。
5. 补齐入口、命名和必要互动的检查，并更新发布成品入口列表和 CI 路径。`check-all.mjs` 会从登记表发现游戏的 Node 测试目录。
6. 按[验证与发布](deployment.md)准备发布包、核对资源和存档、检查实际页面后上线。发布器统一排除各游戏的 `docs/`、`tests/`、`art/`、`tools/`、`dev/`，这些目录不用于游戏运行资源。

## 文件迁移

移动文件时一并更新相对导入、文档链接、命令、CI 和发布边界。先比较整理前后的发布目录；纯归档应逐字节一致。若任务也调整运行内容，单独列出运行差异并做相应浏览器回归。历史记录中的路径可以跟随迁移更新，原有结论和检查结果保留。
