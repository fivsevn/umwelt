# 花农时代承放关系

2026-10-12。正式目录接入本轮 Blender 与 Pixelorama 制作的 294 件物品；植物、37 款原盆器、86 款枪械与兵器保留原 ID、名称、来源、说明及选择机制。原家具不再出现在正式目录。北天台、南阳台、车库房间与独立房间的新初始陈列均为空，用户重新手摆。原作者陈列只存于 `tests/fixtures` 作为历史及照料测试资料。

## 同一套实际尺寸

`rooftop/item-catalog.mjs` 和生成的 `item-data.mjs` 提供原生模型、实际边界、接触范围、承托面、开口及来源资料。物品三轴统一采用 `ITEM_METRES_TO_UNITS = 5.6 / 3`，布局平面仍为 16 个布局单位对应一个世界单位。模型与所有表面、孔径、净高只换算一次，再乘实例缩放；背景建筑的历史坐标比例不用于物品。

所有原生物品的实际接触面为局部高度零。`contactOffset` 不再从植物图片裁剪或缩略尺寸推算。偏心接触与器身使用原生边界中心。源资料中的 Blender X/Y/Z 转为模型 X/高度/负 Z，保存旋转与 `surfacePoint` 一致，Three 模型父级绕 Y 轴使用负保存角度。

`3d/placement-profiles.mjs` 按植物、架子、桌椅与居室、栽培与盛放、日用与照明、收藏、枪械、兵器登记完整目录。植物原仙人掌、多肉等子类筛选继续保留，空间主类为植物。物件的承托角色由实际表面决定，未知类型抛错；不设置凭名称允许放置的界面例外。

`supportSurfaces` 高度指真实板顶或内底，表面 ID 不随中文名称变更。花架每一层保留独立稳定 ID。中间层净高来自模型资料，上层开敞表面无顶盖限高。金属网格和篮架底的支撑条直接读取真实导出的条杆位置与宽度，小底不能悬在格孔中。

## 容器和植物

开放容器的内底、口沿、净内深和最窄开口分别登记。净内深不是器物上方的屋顶；枝叶可以伸出口沿。完整器身须能通过开口并落在真实内底，圆与椭圆开口同时核对实际两轴。特殊不圆内底采用批准的保守内接椭圆，保留原轴比，不虚称整个外轮廓可承重。排水孔是真实通道，在承托检查中排除其范围。

原盆器选择和植物适盆限制仍由原 `botany.mjs` 决定。`getPlantAssembly` 以所选原生盆的真实内底、口沿和开口定位土面，再按该植株原稿的展示土面与盆心移动植株。盆体高度、盆口范围与整体植株高度都来自同一模型资料，取消旧缩略图尺寸及额外放大系数。泡沫栽培箱、已有水体的鱼缸与鱼盆保持已填充状态，不生成可放物件的空腔；原空泡沫箱仍是独立选项。

## 统一编辑与承放链

`support: {id: "父物件 ID", surface: "shelf-2"}` 保存实际层位，`support: null` 表示落地。新物件缺少该字段也不会自动吸附到重叠的花架。物品目录以稳定 ID 保存；少量旧类型只供显式导入兼容，映射到新模型，不产生旧家具目录行。

拖动、微调、旋转、缩放、放在表面和取出使用同一套 `fitsSurface`、`placeOnSurface`、`resolveSupports`、`clearPlacement`。放置核对底部、器身、开口、孔洞、实体框架和净高。嵌套容器不会抹掉祖先花架的净高：容器中的高植株也须避开上一层板。落地植株的冠顶同样不能穿过其上方的实体桌面。

模型导出的部件边界提供实体障碍。中空壁的包围盒不填满其空腔，该空腔改由内底、口沿、开口和孔洞约束；闭合柜体不提供虚假内部空间。带盖器物的实例在有承放内容时打开盖，原稿与缓存模型保持完整。

台下或架下地面根据实际腿间范围与第一层板的底部生成。该区 `bearing: ground` 不生成承放依赖；移动家具后，地上物件仍留在地上。`accessibleContents` 同时列出承放后代和独立地面物件，实体台面不能让下方物件失去取出入口。取出和新增物件用 `findGroundPlacement` 寻找真实可用地面，并仍可普通缩放。

移动、转向和缩放父物件携带所有承放后代，保留种子、花盆和稳定层位。撤销与重做保持整次手势一条记录。移除仍有内容的父物件须先处理内容。`createPlacementContext` 只在一个未改变的布局快照内复用。

## 保存与初始空场景

保持历史存储键 `umwelt-rooftop-layout-v1`，新布局登记 `catalogRevision: native-items-294-v1`。按用户明确决定，首次读取旧目录版本的车库或房间陈列会更新为空白新版基线，不保留旧陈列备份，也不添加恢复界面。今后本版手摆保存正常读取，不重复清空。原人物换装键、资料目录、日志、天气和季节机制保持独立。

公共南北观察页始终投影为空场景，不写回布局；本版已有房间布置照常供独立房间读取。空背景测试和独立物品查看页维持分开，不设置统一导航。这些契约与部署状态分别核对。

## 验证

`tests/rooftop-native-items.test.mjs` 深比较原植物、盆器及兵器资料，核对 294 项源文件摘要、缩略来源、统一比例、开口与所有适盆组合。

`tests/rooftop-spatial-layout.test.mjs` 检查原生表面、真实格条、嵌套高度、祖先净高、孔洞、非圆内底、移动旋转、自由地面、取物与普通缩放。历史几何的数值断言留在独立历史 fixture，旧审计不作为新模型证据。

`tests/rooftop-layout-storage.test.mjs` 检查旧陈列只清空一次、新陈列持久化、公共页不写存储与共享房间数据。原照料、天气与居民测试使用明确有植物的历史派生 fixture，避免因初始为空而丢失浇水、修剪、照料与躲雨覆盖。

浏览器房间、车库、维护与天气套件使用明确的新原生布置 fixture，保留清空/撤销、跨页共享、导出导入、选择拖动、刷新与天气覆盖。实际页面和发布产物由交付代理分别验收；脚本或本地查看通过不代表已线上发布。
