# 花农时代承放关系

2026-10-08。初始布局采用作者的 `horticultural-era-rooftop-layout-4.json`：北天台 86 件、南阳台 20 件、房间 19 件。保留原有身份、坐标、种子、花盆、缩放与朝向；已有本机存档继续优先读取，车库的“初始陈列”恢复当前场景。

## 规格与职责

- `3d/object-dimensions.mjs` 保留物件的宽、深、高，供构造与放置共同读取。
- `3d/placement-profiles.mjs` 定义空间角色、实际盆底或承重脚的范围、可承放表面及层间净高。表面有稳定的 `id`，高度指板顶而非板中心。花架构造直接读取层板表面；修改层数或层高应改这里。
- `3d/plant-envelope.mjs` 运行相同种子的植物构造，测量植株高度。枝叶可以探出盆和层板；盆底必须获得支撑，冠顶需避开上一层板或遮雨罩。
- `3d/vessel-models.mjs` 的 `vesselDimensions` 与 `vesselInterior` 提供中空器物的统一尺度、底面、最窄内径与盆沿。四方向付按馆藏高宽比例构造，并缩小整体尺度以保留原花架位置；圆角方口与鼠志野的圆形内底使用各自的真实开口。容器检查完整器身范围，不能只把小盆底穿过一个过小的开口。
- `3d/spatial-layout.mjs` 解析承放链、验证表面、转换父物件局部坐标，并携带全部嵌套物件移动、旋转。环、失效的层位和缺失父物件均无效。
- `placement-editor.mjs` 只管理“放在”和“层位”控件；拖动射线和界面使用相同表面与验证方法。

物件坐标仍使用历史平面布局单位，16 单位等于一个 3D 世界单位。植物的历史图片中心通过 `contactOffset` 换算为盆底锚点；不可把叶片中心用于父子转换。承重范围与绘制轮廓独立，因此桌沿、伞面和植物叶片的正常伸出不会阻止贴墙放置。

## 存档和编辑

可选字段 `support: {id: "父物件 ID", surface: "middle"}` 明确记录层位。`support: null` 表示主动放在地面；缺少字段的旧存档使用兼容的自动判断，不改写作者初始布局。旧存档真实承重点稍微越界时，仅迁移根物件（阳台最多 8 像素，房间最多 32 像素），并带着承放的整组一起移动、固定原层位；显式承放和显式地面位置仍严格校验。格式保留版本 2、历史本机键与房间版本 2；`spaceVersion: 1` 标记这一套空间定义的迁移已经完成。

移动和旋转家具时，子物件按真实接触点一起变换。缩放家具改变子物件的相对位置，不自动改变子物件的大小；若层间或边缘容不下则拒绝操作。有内容的家具需先移走内容再移除，避免留下悬空物件。通过层位控件承放时，优先选择离台面中心最近的空位置；同层器物的硬质底部不重叠，枝叶仍可自然交错。

指针按下时固定手势归属。开始拖动物件后，不能重新拾取空背景并切换成转动视角；第二根手指和滚轮也不能在这次物件手势中改动视角。空背景仍可以独立观察。

目录先显示全部植物（110 种），然后是承放家具（28 种）、可叠放的承放物件（47 种）、其余摆放物件（119 种）。分类按钮使用同一顺序。`SPACE_GROUPS` 是完整目录的唯一角色定义；未知 ID 抛错，不能静默落入“小物”。

承放家具包括花架、桌椅台面、柜床箱桶和水池台；可叠放承放物件包括玻璃罩、空容器和独立花盆花器。两者都可以按实际尺寸叠放在其他承放面上，不设置“家具只能落地”的类型限制。旧存档的自动推断保留原落地家具习惯，主动选择表面不受该兼容规则限制。已种植的箱盘、食盆和已有水体的鱼缸不提供内部空面。泡沫箱木台只绘制木台，泡沫栽培箱是独立可选、可取出的物件。

水池台只有一个连续台面定义 `counter`，用 `holes` 排除真实池口；台面所有容得下承重底部的地方均可用。池内 `inside` 是唯一中央落点，落在碗底，最多占用一件。水池结构与放置共享 `washstationSpec`。旧 `front/back` 台面与木台 `soil` 绑定迁移到新定义；旧版把物件放在已填满的箱盆里的绑定会单独重新安置，保持其 ID，不清空整个存档。

`supportSurfaces` 只返回随父物件移动的真实板面和内部底面；`placementSpaces` 再加入实际开放的台下/床下地面。地面区的 `bearing: 'ground'` 不生成父子关系，选择后保存 `support: null`，移动家具时仍留在地上。家具已有下层板时，该板照常定义为承放面并携带物件。`spaceObstacles` 描述脚、横撑、柜体、床头、水槽碗体和管道；台下净高、器身范围与这些障碍共同决定能否放入。没有开放底部的箱柜不得创建虚假台下空间。

`fitsSurface` 检查接触底、开口、净高、台面孔洞、障碍及单点规则；`clearPlacement` 同时用于控件、拖动、旋转、缩放、键盘微调，检查相邻硬质底部、容器壁和实体结构。枝叶横向交错允许，植株高度仍须避开层板。修复一个物件时只复核受影响的关系，不因存档其他地方的旧重叠而锁死整个编辑器。

2026-10-10 的金属层架由 `rack-grid.mjs` 共用铁条宽 0.125、中心间距 0.25，留下 0.125 的真实方孔。`stand-models.mjs` 读取同一规格，板顶及稳定层位 ID 沿用原定义；推车板厚仍为实际 0.06。表面的 `lattice` 随父物件缩放，宽底跨孔，小底的承重点须落在铁条上。开孔检查进入统一 `fitsSurface`，没有界面例外。初始陈列和存档格式不重写。

玻璃和透明罩的面仅作为后备拾取对象，优先命中透过玻璃可见的物件；实体框架仍可直接选中。选中承放物件后“取物”列出其所有承放后代，保证深盆、遮挡层板中的物件也能独立选中、移走或收回。

## 回归验证

`tests/rooftop-spatial-layout.test.mjs` 检查完整目录规格、层位、植株净高、容器底与台面的区别、嵌套移动、失效承放链、贴墙与存档。`tests/browser/rooftop-models.cjs` 用实际选择控件、拾取、拖动、旋转、移除与刷新验证第二层和视角归属。`tests/browser/rooftop-garage-layout.cjs` 检查车库房间在宽屏使用工作区和手机上的较高画布；`tests/browser/rooftop-room.cjs` 检查独立房间以及 1600、900、390、320 宽度。

## 连续操作与绘制预算

拖动事件只记录最新指针位置，在下一次绘制前处理一次；释放、取消和丢失指针捕获前提交最后位置，整次拖动仍是一条撤销记录。“放在／层位”在选中与放下时计算完整选项，拖动中只更新当前承放关系。`createPlacementContext` 复用同一布局快照的承放链、物件规格与表面；布局改变后必须重新创建，不能跨编辑保存上下文。

模型的几何身份只包含类型、种子、花盆等构造参数，普通位置、旋转、大小和层位变化直接更新模型变换。垂吊植物仍按真实地面与花架边缘重新计算裁剪范围，防止枝条穿地。渲染器对每个更新后的布局数组缓存承放链，`syncLayout` 会建立新数组。

拿出新物件或复制时，`findGroundPlacement` 从离原位置最近的候选点开始，用同一实体障碍和承放链检查实际空位，优先留出少许空间；没有空位时不再退回一个穿过家具的位置。新植物先确定种子再计算尺寸。层位搜索先排除尺寸和净高不可能满足的表面，只搜索器身容得下的网格区域；拖动复用渲染器已解析的承放链和本次快照的盆底规格。

主游戏拖动旋转只更新相机，布局保持只读。交互时以浏览器动画帧绘制，静止时保持约 30 次每秒的植物、人物和天气运动。`3d/render-budget.mjs` 限制大屏绘制缓冲为最多 160 万像素、最长边 1600 像素，手机与普通编辑画布保留原分辨率；拾取和门的位置仍按实际显示尺寸计算。车库房间画布在电脑随工作区扩展为 4:3，手机使用宽高 1:1.12 来放大室内细节，避免 340 像素限制。

## 后续扩容

新增物件同时登记目录角色、真实尺寸、表面/内部底面、净高和实体障碍；不新增散落在界面中的类型白名单。若结构与现有家具不同，新增相应空间配方与规则测试。新表面 ID 不随中文标签改变。`rooftop/AGENTS.md` 将这套要求作为本目录维护规范；完整目录测试核对角色无重复、无遗漏且承放角色和实际表面一致。地面区域必须独立于承放链，模型构造只读取真实表面。

木阶与梯形木花架的旧踏板深度约 10 个布局单位，容不下默认盆底。两者改为每层约 31 个单位的深踏板，模型条板和承放范围共同读取尺寸；高层退后，低层物件仍须避开其上方踏板。每层下方还分别开放真实地面空隙。旧存档的显式层位按新旧踏板中心的差值迁移一次，随物件携带其嵌套内容；扩大的根花架若贴近边界则小幅内移，确实放不进狭窄区域时逐步缩小，保持身份和层位。作者初始布局继续保持原有 86/20/19 件及其坐标。
